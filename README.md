# AudioHub

**把多台设备的声音汇聚到同一副耳机或音箱。** AudioHub 可在同一局域网内连接 Android 手机和 Windows 电脑，将多路声音混合后从一台设备播放，并在已连接设备之间手动传送剪贴板文本。

[GitHub 项目仓库](https://github.com/typeadfe/AudioHub)

## 它解决什么需求

电脑在工作或者游戏时想要使用其他设备，但声音通常分散在不同设备上。AudioHub 让其中一台手机或电脑充当接收端，把其他设备的声音集中播放。电脑本机原有的声音也可与接收到的声音一起从当前输出设备播放，无需反复切换耳机。

适用场景包括多个手机/电脑共用耳机或音箱、手机声音汇入电脑、多个音源同时监听，以及在已连接设备间快速传递一段文字。它面向同一 Wi-Fi／局域网使用，不依赖蓝牙音频连接。

## 主要功能

- **多路混音：**接收端可同时播放多台发送设备的声音，并分别调节音量或静音。
- **双端收发：**Android 与 Windows 都提供发送和接收界面；Android 发送本机播放的声音，Windows 可发送本机系统声音。
- **手动发现：**点击“扫描设备”才搜索新设备；已有连接会保持，并在断开后尝试重连。降低后台资源使用。
- **剪贴板互传：**连接建立后，任一端都可以点击“发送剪贴板”；收到文本时给出提醒。
- **发送端设置：**Android 发送端可调整音频质量、延迟与 Wi-Fi 发送带宽。

## 使用方法

1. 让设备接入同一局域网，在作为播放设备的手机或电脑上点击“开始接收”。
2. 在发送设备上扫描并连接接收端，然后点击“开始发送”。
3. 需要传文字时，在任一已连接设备上点击“发送剪贴板”。

Android 需要 10 或更高版本。首次发送声音时，系统会请求录屏／音频捕获权限；禁止被录制的应用声音无法采集。Windows 版为免安装 EXE。

## 下载

v1.0 文件：`AudioHub-v1.0-debug.apk`（Android）和 `AudioHub-Windows-v1.0.exe`（Windows）。当前 Android 文件使用开发签名，适合测试；正式发布需使用专用发布签名重新打包。Windows 文件尚未签名，系统可能提示发布者未知。

## 项目结构

- `android-source/`：Android 应用
- `windows-player/`：Windows C++ 应用
- `assets/`：图标源文件

构建脚本位于 `tools/` 和 `windows-player/build.bat`。当前脚本包含开发机路径，在其他电脑构建时需按当地环境配置 JDK、Android SDK、Gradle 和 MinGW。项目所有者发布源码前还需确定并加入许可证文件。
